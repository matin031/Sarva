# ساختن یک امتحان نهاییِ تازه

این پوشه دو فایلِ نمونه دارد که هرکدام **هر ۱۸ نوع سؤال** را یک‌بار نشان می‌دهند:

| فایل | درس | از رویش چه بسازیم |
|---|---|---|
| [`nemoone-farsi.ts`](./nemoone-farsi.ts) | فارسی (۱، ۲، ۳) | قلمرو زبانی / ادبی / فکری |
| [`nemoone-olum-fonoon.ts`](./nemoone-olum-fonoon.ts) | علوم و فنون ادبی (۱، ۲، ۳) | تاریخ ادبیات / سبک‌شناسی / موسیقی شعر / زیبایی‌شناسی / نقد و تحلیل |

نمونه‌ها فقط متن نیستند؛ TypeScript واقعی‌اند و در `tests/exam/seed-papers.test.ts`
سنجیده می‌شوند، پس اگر قاعده‌ای عوض شود، همین‌جا سر و صدا می‌کند.

دو آزمونِ واقعیِ داخل پروژه هم نمونهٔ کاملی‌اند:
`lib/exam/seed-data/12/farsi3/farsi3-1403-kherdad.ts` و
`lib/exam/seed-data/12/olum-fonoon3/olum-fonoon3-1405-mordad.ts`.

پوشه‌بندی: `lib/exam/seed-data/<پایه>/<کتاب>/<کتاب>-<سال>-<ماه>.ts`

```
seed-data/
  index.ts          ← فهرستِ همهٔ آزمون‌ها (تنها جایی که ثبت می‌شوند)
  lint.ts           ← سنجشِ ساختار و زیرخط
  12/farsi3/        ← فارسی ۳، دوازدهم
  12/olum-fonoon3/  ← علوم و فنون ادبی ۳، دوازدهم
```

## روال کار

```bash
# ۱. فایل تازه از روی نمونه (importها را به "../../helpers" و "../../seed-types" عوض کن)
cp docs/exam-authoring/nemoone-olum-fonoon.ts \
   lib/exam/seed-data/12/olum-fonoon3/olum-fonoon3-1406-khordad.ts

# ۲. سؤال‌ها را از برگه و کلیدها را از «راهنمای تصحیح» بنویس
#    (subject/grade/title/examSession/sourcePdf بالای فایل را هم عوض کن)

# ۳. در lib/exam/seed-data/index.ts ثبتش کن (seed، سنجش، پیش‌نمایش و تست
#    همه از همان فهرست می‌خوانند)

# ۴. بسنج (به دیتابیس نیاز ندارد)
npm run exam:validate

# ۵. وارد کن (DATABASE_URL لازم است). فقط آزمون‌های تازه اضافه می‌شوند؛
#    آزمونِ موجود با --replace=<examSession> جایگزین می‌شود — و کارنامه‌هایش پاک.
npm run db:seed-exams -- --dry-run
npm run db:seed-exams
```

بعد از آن، آزمون در `/exam` زیر درس و پایهٔ خودش می‌آید و آدرسش
`/exam/<examSession>` است. برای دیدنِ برگه بدون دیتابیس:
`/exam-preview?exam=<examSession>`.

## زیرخط

اگر برگه می‌گوید «واژهٔ مشخص‌شده» یا «زیر آن خط کشیده شده»، همان واژه روی صفحه
باید زیرخط داشته باشد؛ `exam:validate` نبودنش را خطا می‌گیرد.

- داخلِ passage/stimulus: توکنِ `highlight` (`highlight1`، `highlightThenBlank`)
- داخلِ هر رشتهٔ دیگر (instruction، questionText، statementText، متنِ گزینه،
  آیتم‌های فهرست): `ul()` از helpers یا `{{واژه}}`

```ts
instruction: `«به سوزی ده کلامم را روایی / کز آن گرمی کند ${ul("آتش")} گدایی»`,
```

جملهٔ توضیحی مثل «در برگهٔ اصلی این عبارت مشخص شده» ننویس؛ خودش را زیرخط بزن.

## جای خالی

`questionText`ی که «..........» دارد، کادرِ پاسخ را همان‌جا داخلِ جمله نشان
می‌دهد (short-text-answer با یک نقطه‌چین، two-answer-text با یک نقطه‌چین به‌ازای
هر field). اگر تعداد نقطه‌چین‌ها با fieldها نخواند، کادرها زیرِ جمله می‌آیند.

---

## قاعده‌هایی که خطا می‌دهند

- جمعِ `score` جزءهای هر بخش باید دقیقاً `sectionScore` شود، و جمعِ
  `sectionScore`ها دقیقاً `totalScore`.
- `score` هر جزء باید بزرگ‌تر از صفر باشد (CHECK دیتابیس). **سؤالِ حذف‌شده را
  ننویس**؛ نمره‌اش را طبق راهنمای تصحیح به سؤالِ دیگر بده و در `sourceNote`
  بنویس چرا بارمِ آن سؤال با برگه فرق دارد.
- `content.type` باید با `type` همان جزء یکی باشد.
- `mcq-inline` / `mcq-multi-select` / `mcq-plus-correction` دست‌کم دو گزینه و
  دست‌کم یک `isCorrect: true` می‌خواهند.
- `examSession` در کل بانک یکتاست (ستون UNIQUE است) و در آدرس دیده می‌شود؛
  انگلیسی و با خط تیره بنویس: `olum-fonoon-1405-mordad`.
- `subject` نامِ **کتاب** است و نه نامِ درس: `farsi1/2/3` و
  `olum-fonoon1/2/3`. صفحهٔ `/exam` درس را از روی همین پیشوند پیدا می‌کند.

## انتخاب نوع سؤال

شکلِ سؤال روی برگه، نوع را تعیین می‌کند — نه سلیقه:

| روی برگه | نوع | نکته |
|---|---|---|
| چهار گزینهٔ الف/ب/ج/د | `mcq-inline` | `stimulus` برای بیت یا عبارتِ بالای سؤال |
| «دو گزینه را انتخاب کنید» | `mcq-multi-select` | تصحیح همه‌یا‌هیچ |
| «کدام غلط است؟ + درستش را بنویس» | `mcq-plus-correction` | نیمی گزینه، نیمی املا |
| کمانکِ دوگزینه‌ای داخل جمله | `mcq-inline` با دو گزینه | `layoutPattern: "bracket-choice-mcq"` |
| «کدام مصراع؟» بدون برچسبِ الف/ب | `mcq-select-line-in-poem` | پاسخ، شمارهٔ خط است |
| درست / نادرست | `true-false` | با `labels` می‌شود «بله/خیر» کرد |
| جای خالی برای یک اصطلاح | `fill-blank-term` | کادر داخلِ خودِ جمله می‌آید |
| «معنی واژهٔ مشخص‌شده» | `word-meaning-input` | واژه زیرخط‌دار سرِ جایش می‌ماند |
| پاسخِ یک‌واژه‌ای | `short-text-answer` + `inputVariant: "word"` | کادرِ کوتاه = «یک واژه بنویس» |
| پاسخِ یک‌سطری | `short-text-answer` | پیش‌فرض |
| مفهوم‌نویسی | `short-text-answer` + `inputVariant: "textarea"` | معمولاً تصحیحِ خودکار ندارد |
| دو (یا سه) جای خالی در یک جمله | `two-answer-text` | ترتیبِ خانه‌ها مهم است |
| «چند مورد؟» | `count-answer` | پاسخ فقط عدد |
| جدولِ ستون الف ← ستون ب | `matching-pairs-with-distractor` | ستون ب یکی بیشتر باشد |
| چند عبارت، جلوی هرکدام یک فهرست | `multi-part-inline-tagging` | با `weights` نمرهٔ جزئی |
| مرتب‌کردن واژه‌ها/ارکان | `word-reorder-dnd` | کشیدن‌ورهاکردن |
| شعر حفظی، مصراع دوم | `verse-completion` | |
| نمودار پیکانیِ گروه اسمی | `diagram-builder` | `mode: "dependency-select"` |
| فهرست، «n غلط را بیاب» | `find-n-errors-in-list` | نمره به نسبتِ موردهای درست |
| فهرستِ جفت‌ها، هرکدام درست/نادرست | `paired-list-error-correction` | |
| متنی که یک غلط دارد | `open-error-correction-in-passage` | بدون فهرست |

`layoutPattern` فقط برچسبِ چیدمان است (multi-subquestion، bracket-choice-mcq،
multi-item-true-false، multi-paraphrase-block، list-of-parallel-blanks) و هیچ
اثری روی نمایش یا تصحیح ندارد.

## تصحیح

`gradingMode: "exact_match"` یعنی همان لحظه خودکار تصحیح می‌شود. هر مقدار
دیگری (`ai_semantic`، `ai_partial_credit`، `manual`) یعنی **خودارزیابی**:
دانش‌آموز پاسخِ درست را می‌بیند و خودش نمره می‌دهد. پس:

> هر جا پاسخ از یک مجموعهٔ بسته می‌آید (نام آرایه، نام قلمرو، یک واژه از خودِ
> بیت)، `exact_match` بگذار — حتی اگر برگه «بنویسید» گفته باشد. اگر لازم شد،
> همان سؤال را گزینه‌ای کن و در `sourceNote` بنویس گزینه‌ها از کجا آمده‌اند.

مقایسهٔ پاسخ، این‌ها را نادیده می‌گیرد: نیم‌فاصله در برابر فاصله، «ي/ك» عربی،
اعراب، همزهٔ روی «ه» («خانهٔ» = «خانه») و نشانه‌گذاری. مترادف را نادیده
نمی‌گیرد — هر صورتِ محتمل را در `accepted` بیاور.

## دو تلهٔ رایج

- **ترتیب در `two-answer-text`.** خانه‌ها جدا تصحیح می‌شوند، پس اگر پاسخ‌ها
  جابه‌جاشدنی‌اند (مثلاً «دو آرایه را بنویسید»)، `mcq-multi-select` بگذار تا
  ترتیب، نمرهٔ کسی را نبرد.
- **نشانه‌های هجایی.** «– U – –» داخلِ متنِ راست‌به‌چپ وارونه دیده می‌شود و
  معنایش عوض می‌شود. به‌جایش «بلند، کوتاه، بلند، بلند» بنویس.

## `verified` و `sourceNote`

`verified: false` یعنی «این را یک آدم باید با برگهٔ اصلی بسنجد»؛ خروجیِ
`npm run exam:validate` همهٔ این موردها را فهرست می‌کند. هر جا از روی حدس
نوشتی یا چیزی به برگه اضافه کردی (گزینهٔ ساختگی، تغییر بارم)، در `sourceNote`
بنویس چه شد و چرا.
